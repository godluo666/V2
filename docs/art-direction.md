# 美术设计方案 ——「月汐町·结缘坂」

> 当前权威版本：2026-08-24。本文覆盖此前“一番街十字路口、高楼媒体塔、霓虹都市”方向；
> 旧方案只保留在需求历史中，不得重新接回运行场景。

## 1. 核心体验

结缘坂是一条有人真实生活、营业和停留的缓坡住宅街。构图可以借鉴日本动画中“街道转弯后仍有
世界”的空间叙事，但建筑、店名、图形、人物与道具均为《月汐町》原创。玩家从西入口进入，
道路轻微上坡并缓慢转弯，远端始终被树冠、错位住宅和坡顶屋檐自然遮住，使人想继续往前走，
同时不能产生小盒子地图或被墙堵死的感觉。

- 现实城市结构是第一层，动画化取舍是第二层。
- 所有近景重要物件必须有体积、厚度、支撑、接触和合理用途，不用整面贴图代替模型。
- 信息密度来自建筑进退、门窗、生活设施、植物和使用痕迹，不来自巨型广告、霓虹堆叠或随机摆件。
- 关闭 UI、发光招牌和后期效果后，街道仍应像有人长期居住和经营的真实地方。

## 2. 街道骨架与尺度

- 可玩边界为 `84m × 36m`（x = -42..42，z = -18..18）。
- 机动车道约 `5.2m`，两侧步道约 `1.1m`；这是安静的街坊道路，不是商业大道。
- 中心线带连续缓弯，地面从西向东约上升 `2.8m`。地面、建筑、碰撞、NPC、交互点和镜头必须
  共同使用 `streetCenterZ` / `streetHeight`，禁止视觉模型与业务坐标分离。
- 西入口保留清晰到达感。其余旧户外结构全部让位于连续低层街墙、真实支路、树下棋摊和坡道端景。
- 主要停留点包括店门口、四处住宅门槛、花店前、服务小巷、十二级坡梯、树下棋摊、长椅和场馆门厅。
- 相机在正常角色高度仍能看见中远景屋顶、树冠和天空层次；不得靠缩短雾距或近墙遮挡制造“紧凑”。

`shared/src/cityplan.ts` 是建筑、道路和入口的唯一数据源，`shared/src/layouts.ts` 是碰撞、设施、
NPC 与交互点的唯一数据源。客户端渲染、服务端移动和测试必须消费同一契约。

## 3. 建筑与店铺

- 活跃街墙只允许 2～3 层的 `shopfront`、`apartment`、`backstreet` 三类低层体量。
- 禁止高楼、媒体塔、巨大轮廓盒、赛博龙门架和悬空广告屏重新进入运行时总装。
- 一层必须按用途表达：杂货/文具/药房有货架与商品；花店有花桶、茎叶与盆栽；咖啡店有吧台、
  杯具、点心与咖啡机；洗衣店有滚筒、门圈、控制面板和洗涤用品；餐馆有暖帘、柜台、碗碟；
  鱼店有冰台、鱼货和价签；钟表维修有工作台、卷帘与小型陈列。
- 上层住宅要有可读的窗洞深度、窗框、窗帘、阳台、栏杆、晾衣杆、空调外机、水电表、雨水管、
  屋檐和屋顶小设备。相邻建筑在高度、退界、屋顶和开间上错落，不能复制成同一排盒子。
- 墙面使用代码原生的低对比水渍、补漆、细裂纹和底部污痕；痕迹服从排水与使用逻辑，不做随机噪声。

## 4. 生活细节与自然

- 自行车必须有车架、车轮、辐条、车篮或停车支撑；售货机必须有机壳、展示仓、货架、商品、按钮、
  投币区、取货口和散热缝；路灯、壁灯、电线与晾衣绳必须看得到真实支撑。
- 标准细节库包含盆栽、猫、信箱、饮料机、小招牌、晾衣杆、空调外机、电线杆、长椅、排水沟、
  雨水篦、井盖、回收桶、服务表箱、反光镜、门牌、快递箱、雨伞筒、扫帚和店前周转筐。
- 道具按“门前生活簇”“店铺营业簇”“市政维护簇”组织，保留 1.2m 以上有效通路，不平均撒满地图。
- 九棵主树形成连续树荫；每棵近景树都有土壤、树池边缘、护根格栅或支撑。墙边爬藤、院内灌木、
  路边野花和少量落叶提供季节与维护差异，远景再用实例化山脊树冠形成纵深。
- 猫、飘叶和晾衣具有轻微动画，但不能喧宾夺主，也不能穿过墙体或地面。

## 5. 光线、色彩与材质

- 基准时段为下午 4～6 点的暖阳，不做红色灾难式晚霞。
- 阳光偏奶油橙，建筑阴影偏低饱和蓝紫；窗灯和店灯只作小面积暖点。
- 主色为低饱和米白、浅木、浅灰、灰绿和土色，少量橙黄用于灯光与视觉焦点。
- 路面、石材、木材、金属、玻璃和织物必须通过粗糙度、反射与真实层级区分，不能只换颜色。
- 实时灯数量克制；每一盏点光源必须对应可见灯具。Bloom 和饱和度不得掩盖模型缺失。

## 6. 树下实体飞行棋

- 飞行棋位于树荫下的真实地摊院落，有矮墙、压顶、织物旗、低木棋盘、四方坐垫、收纳箱、浇水壶
  和街坊招牌；庭院地面有石材接缝、修补和排水关系。
- 2D 面板必须以完整图形棋盘为主：52 格环形路线、四组基地与归位孔、四条终点跑道、起飞/跳跃提示、
  中央骰子和 16 枚权威棋子。文字只负责短状态，不承担规则图解。
- 3D 棋盘与服务端使用同一棋局状态。玩家可直接点击实体骰子加入、掷骰或无合法棋时过回合；点击发光
  实体飞机选择并移动，能够在棋盘旁完成加入、行动、结束、重赛的完整循环。
- 棋子归位、轨道堆叠、终点与可选高亮必须可视化；棋子有机身、头部、翼与机鼻，不能用文字标签或
  单个彩球代替。

## 7. 性能与原创边界

- 优先使用程序化几何、合并网格与实例化。远景住宅和山脊可批处理，但正常角色近景不以贴片替代实体。
- 不从网络拼贴建筑、道具或整景图片；CanvasTexture 仅用于店名、价签、公告与低频图形信息。
- 重复构件可共享几何与材质，重要店铺仍必须有与经营内容匹配的专属实体。
- 画质分级可以减少阴影和远景细分，但不得删除碰撞、入口、棋局状态或造成悬浮。

## 8. 完成判定

1. 从西入口正常角色视角能读出弯道、坡度、中远景屋顶与树冠，看不到道路尽头但不觉得视野狭窄。
2. 连续步行可到达三场馆、全部店前停留点、坡梯、服务小巷与棋摊，视觉地面和权威碰撞一致。
3. 所有活跃建筑都是 2～3 层，并能从近景识别店铺用途和住宅生活层。
4. 电线、灯具、空调、雨水、门槛、排水、树池与店前物品均有支撑和落地关系，没有悬空装饰。
5. 关闭 UI 与后期仍呈现低饱和暖阳下的真实住宅街，而不是贴图布景、道具仓库或封闭小地图。
6. 飞行棋在 2D 和 3D 都清晰图形化，并可仅通过实体棋盘完成一个服务器权威回合。
7. 类型检查、共享布局、棋局与对话测试、生产构建通过；真实浏览器画面必须另行人工审视，代码存在
   不能替代可视证据。
