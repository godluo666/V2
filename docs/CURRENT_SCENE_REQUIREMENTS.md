# 《月汐町》当前场景需求基线

> 状态：已确认  
> 基线日期：2026-07-30  
> 当前实现分支：`agent/sunny-town`

这份文件记录已经确认的场景方向和不可回退项。后续增加场馆、玩法、家具或活动时，
先在“增量需求记录”追加条目，再修改共享布局、客户端表现、服务端规则和云端验收。

## 1. 不可回退的产品约束

- 保持现有团子角色的模型、配色能力、动画、控制手感和联机表现不变。
- 所有运行依赖、脚本、资源声明和测试依赖只能位于当前仓库内；不依赖全局安装或仓库外文件。
- 不在本地运行测试、构建或浏览器验收。验证统一交给 GitHub Actions 云端工作区。
- 当前首阶段街区只保留三个可进入场馆：
  - 星汐电影院
  - 团子轰趴馆
  - 镜界电竞观战馆
- 旧咖啡馆、便利店、游戏厅、团子塔和车站不出现在当前街道，也不提供入口。

## 2. 一番街户外基线

- 街道参考 P5 涩谷街头的“高对比、斜向构图、密集招牌、漫画都市节奏”，但不复制其
  商标、角色、字体、地图、贴图或具体美术资产；最终视觉必须是《月汐町》的原创表达。
- 画面要绚烂、明媚、有阳光，同时保持角色、入口、路面和交互提示清晰可读。
- 使用一条约 `58m` 的东西向生活街，整个可玩边界约 `62m × 46m`；不再用大广场、
  大十字路口、长支路或空旷车站区域制造距离。
- 三个场馆嵌在连续住宅立面里，住宅、公寓、阳台、雨棚、海报、电线、自行车和花槽
  共同形成“紧凑的一条街”。
- 路面使用深墨沥青作为构图底色，以红、青、黄的小面积图形、招牌和灯带提亮。
- 入口前、出生点和主步行带保持净空；装饰物靠步道边缘成组布置。
- 户外服务端碰撞、客户端渲染和云端浏览器路径的唯一坐标来源是
  `shared/src/cityplan.ts`，不得另写一套散落坐标。

## 3. 三个场馆基线

### 星汐电影院

- 保留巨幕与 50 个座位，座区采用 5 排、三段分组和宽过道。
- 椅脚必须落在地面或对应排的台阶顶面；台阶高度、椅子原点、坐下吸附点和角色高度
  使用同一份共享布局数据，禁止仅靠视觉偏移修补浮空。
- 视频、YouTube 和控制栏必须显示同一个房间权威播放状态。

### 团子轰趴馆

- 氛围参考温馨社团活动室：奶油墙面、暖木地板、软毯、围坐沙发、茶水零食台、
  阅读角、社团活动板、照片奖杯墙、小舞台和点歌机。
- 保留可玩的服务端权威象棋桌。
- 放置一张有四方座位和棋子的飞行棋桌。首阶段它是可围坐的实体桌游陈设；
  若以后增加在线规则，必须走服务端权威状态，不能伪装成已联机玩法。
- 家具沿墙或成组放置，中部和入口保留通行空间，整体温馨但不拥挤。

### 镜界电竞观战馆

- 保留中央联赛大屏、观战区、机位和清晰主通道。
- 使用蓝青强调光配合暖色前台，避免压抑的纯黑网吧效果。
- 大屏共享播放状态与电影院使用同一套媒体同步基础设施。

## 4. 媒体同步基线

- 参考 VideoTogether 的同步思想：房间状态携带播放时间、暂停状态、播放速度和更新时间；
  客户端通过请求往返时间中点估计服务器时钟偏移。
- 服务端是媒体状态、修订号和房间广播的唯一权威来源。
- 所有玩家的进度条根据“服务器时间 + 权威媒体锚点”计算，不读取各自视频元素的本地
  `currentTime` 作为 UI 真值。
- 客户端忽略旧修订，断线重连和晚加入时使用最新快照恢复。
- 播放中的漂移策略：
  - `≤ 150ms`：保持正常速率；
  - `150–500ms`：支持细粒度速率的平台用约 `±3%` 的短时微调；
  - `> 500ms`：跳转到权威时间；
  - 暂停状态出现超过 `150ms` 的偏差时直接对齐。
- 缓冲期间不反复跳转；恢复可播放后重新对齐。
- 任意跨域网页 iframe 内的视频无法由宿主页可靠控制，不得虚假宣称同步。一起看内容
  应使用官方 YouTube 适配器或直接视频地址；新增提供方时实现统一 Provider Adapter。

## 5. 本轮完成后的维护性审计

### 已在第二轮优化中收口

- **同步策略重复**：直接视频和 YouTube 不再各自维护一套漂移阈值，统一调用
  `client/src/world3d/media/provider.ts` 的纯函数校正计划；新增 Provider 必须复用它。
- **首次进入可能延迟对齐**：播放器首挂载允许立即跳到权威时间，只有后续连续跳转受冷却限制。
- **YouTube 地址形态单一**：统一解析 `watch`、`youtu.be`、`shorts`、`live` 和
  `youtube-nocookie/embed`，解析规则有独立云端单测。
- **场馆入口信息重复**：入口名称、空间键和坐标统一从 `VENUES` 生成，增加场馆时不再
  同时维护第二张映射表。
- **当前城市被旧设施常量污染**：车站和天桥坐标已从 `shared/src/cityplan.ts` 移除；
  尚未删除的旧程序化预制件只保留本地归档尺寸，不再参与共享城市契约。
- **模块初始化隐式修改数组**：远景楼群改为纯函数生成后一次性合并，避免导入模块时
  对导出数组执行 `push`。
- **无入口旧房间的返回坐标失效**：兼容保留的旧房间统一回到一番街安全出生点，
  避免历史会话或内部跳转回到新边界之外。
- **浏览器旅程看见提示却不互动**：门和银幕交互统一走
  `scripts/browser-driver.mjs`；每次移动后必须重新检查提示、按下真实的 `E`，并等待目标
  空间确认，避免最后一次移动后漏检造成十几分钟的级联假失败。
- **云端低帧率让按键行走超时**：云端浏览器不再把 Three.js 渲染帧率当作移动时钟；
  旅程从最新服务端自身快照出发，以低于角色跑速的小步长走正常 `input` 通道；未被确认
  的一步只会重试，不会累积成本地假位置，服务端仍执行限速、防瞬移、边界、碰撞和门口
  距离校验。斑马线、步道、场馆入口及门前接近点直接读取
  `shared/src/cityplan.ts`；室内返回路线读取共享布局的出口。移动建筑或房门时不需要再
  维护散落在三个脚本里的坐标，坐过椅子后先走正常 `stand` 协议再移动；影院最高排
  验收也从共享布局选择最高座位，并走服务端 `sit` 距离校验和客户端高度吸附。
- **NPC 抢占轰趴馆入口提示**：Rin 的巡游线移动到街道南侧，北侧轰趴馆门前恢复净空；
  角色本身的模型、动画和控制逻辑未改动。
- **联机断言依赖固定等待**：媒体旅程不再假设广播会在固定 `1.2s` 内到达所有后台页；
  `set/seek/pause/rate/play/clear` 都等待两端观察到对应权威状态后再采样，避免把云端调度
  延迟误报成同步漂移。

### 当前仍存在的不足与后续要求

以下项目是已知边界，不得在界面、README 或发布说明里包装成已经完成：

1. **飞行棋还不是联机玩法（P1）**：目前只有棋盘、棋子和四个围坐点。后续实现时要在
   `shared` 定义状态/指令、由 `server` 判定掷骰和行棋、按房间广播，并增加断线重连、
   旁观和云端双人流程；禁止把规则塞进 React 组件。
2. **任意网页 iframe 无法保证同步（平台边界）**：跨域页面不暴露可靠媒体控制接口。
   只能明确提示“网页展示不等于同步播放”，共同看片优先使用已适配 Provider。
3. **进度条总时长依赖本地元数据（P1）**：当前位置已经统一权威，但视频总时长仍由
   Provider 本地上报。后续 Provider Adapter 应提供可靠 duration，并处理直播流、
   元数据失败和不同 CDN 返回不一致的情况。
4. **旧空间构建器仍在主布局文件（P2）**：咖啡馆、旧游戏厅、商店和塔楼大堂为历史
   玩法与个人房间链路保留，但没有街道入口。完成存档迁移方案后，应拆到
   `shared/src/layouts/legacy.ts`，主文件只保留一番街、三场馆和房间壳。
5. **美术验收仍需人工看图（P1）**：云端旅程会生成截图并验证坐标/交互，但当前没有
   稳定的像素基准。每次修改街道构图、日照、影院台阶或轰趴馆家具后，应检查 Actions
   上传的桌面与移动端截图，确认不穿模、不浮空、不过曝且主通道清楚。
6. **设备性能预算缺少长期数据（P2）**：密集招牌、轮廓线和 Bloom 已受控，但尚无真实
   低端设备帧时间统计。后续应在云端旅程记录场景 draw call、首屏时间和长帧比例，
   再决定是否增加质量档，而不是散落设备判断。

维护规则：优先消除“一个概念多份真值”、散落魔法数字和客户端自判联机结果；公共坐标、
协议、状态公式和玩法规则必须分别归属 `shared`/`server` 的明确模块，表现组件只消费数据。

## 7. 新内容接入清单

新增一个场馆或街道内容时，至少检查：

1. 在本文件“增量需求记录”增加需求条目。
2. 在 `shared/src/cityplan.ts` 或 `shared/src/layouts.ts` 增加唯一坐标和交互数据。
3. 在 `client/src/world3d/spaces/registry.tsx` 注册程序化预制件或仓库内资源。
4. 若有多人状态，在 `shared` 协议和 `server` 权威逻辑中实现，客户端只作预测与表现。
5. 更新 `shared/test`、`server/test` 和 `scripts/*.mjs` 的云端验收路径。
6. 只推送到当前账户的 `godluo666/V2`，由 `.github/workflows/cloud-tests.yml` 验证。
